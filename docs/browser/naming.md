# Browser: names from Gecko

Kieran's brief (2026-11-26): in the browser, "name stuff after how it is in Gecko rather than inventing your own
names", and follow Gecko's style of writing for strings and its names of concepts.

This file is phase 1: the rules, a glossary, an inventory of what the browser calls things today, and a plan. Nothing
in `apps/browser` or `crates/ui` changes until Main says go.

- **Two kinds of name.** Code uses Gecko's code name (`SitePermissions`, `Sanitizer`, `SessionStore`). Strings use
  Gecko's UI name ("Clear recent history", "Page info", "Connection secure").
- **One exception: casing.** Gecko's menus are Title Case. Bingux's copy rules are sentence case, and
  `scripts/copy-lint.py` fails Title Case. So: Gecko's words, Bingux's casing (D1).
- **Checked against** the Gecko tree at `FIREFOX_160_0_RELEASE`, on the vivarium box (`/home/node/gecko/src`, read
  only), and against Mozilla's published guidance. Every claim names its file or URL.
- **Catalogue read at** `4a668f66` (369 messages). Other agents are changing it as this is written; re-run the
  checks under "How the Fluent table was made" before phase 2 starts.

## Writing style

Rules for every string in `apps/browser/locale/en-US/browser.ftl`. Each has an example and a source. They sit on top
of `docs/bingux-ui.md`, "Localisation", which already fixes IDs, kind suffixes, attributes, variables, plurals, terms
and the app-copy voice. This adds what Gecko adds.

### S1. Capitalisation

| Element                                   | Gecko                                                                                                  | Bingux rule        |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------ |
| Menu bar, application menu, context menus | Title Case: `New Private Window`, `Clear Recent History…` (MB, AM, BC, TC; AC capitalization)          | Sentence case (D1) |
| Buttons, headings, tooltips, error text   | Sentence case by default: `This site can’t be reached` (NE `neterror-search-cta-title`); `Got it` (DL) | Sentence case      |
| Brand and feature names                   | Capitalised: `Picture-in-Picture`, `Reader View`, `Enhanced Tracking Protection`, `Top Sites` (AC)     | Keep the capitals  |
| Things that are not features              | Lower case in a sentence: `new tab`, `shortcuts`, `passwords` (AC capitalization)                      | Lower case         |
| Acronyms                                  | `URL`, `PDF`, `OK` (AC word list)                                                                      | Same               |

Gecko is not uniform: NE has `Try Again` and `Go Back` as buttons, and AM has `Full screen` beside `New Tab`. Follow
the table, not one string.

### S2. Ellipsis

- Use one character, `…` (U+2026). `three-dots` is a `copy-lint` finding.
- Put it on an item that needs another step before it acts: `Print…`, `Save Page As…`, `Find in Page…`,
  `Clear Recent History…`, `Customize Toolbar…` (MB, AM; AC punctuation).
- Leave it off an item that opens a page or a window of options: `Settings`, `Downloads`, `Learn more` (AC punctuation).
- Not in body text. A title that pauses may keep one: `Loading…`.

### S3. Punctuation

- Curly quotes and apostrophes only: `can’t`, `“{ $query }”`. Gecko checks this by machine (AC punctuation). Ours has
  `engine's` in `browser-settings-security-description`.
- An em dash with a space either side sets thoughts apart: `{ $tabGroupName } — Closed` (TB), `{ $timeLeft } — { $transfer }`
  (DU). The en dash is for ranges (AC punctuation). Ours uses `–` in three window titles and `·` in download lines.
- No full stop on titles, buttons, labels, tooltips and toasts. A full stop ends a body sentence (AC punctuation).
- No exclamation mark unless something is truly good news. Serial comma. Contractions are fine (AC punctuation).

### S4. The product name is a term

- Never write the product's name in a message. Refer to a term: `{ -brand-short-name }` (BR, AM, NE).
- Gecko has five terms in `brand.ftl`: `-brand-shorter-name`, `-brand-short-name`, `-brand-shortcut-name`,
  `-brand-full-name`, `-brand-product-name`. One is enough here.
- Terms are for brand names and shared vocabulary, so a translator changes them in one place (FR, "Terms").
- All catalogues are one bundle (`crates/ui/src/i18n/localiser.rs`, `bundle.add_resource`), so a term needs a name no
  other catalogue uses. Ours: `-browser-brand-name = Browser`.
- Ours today writes `Browser` in 12 messages, for example `A newer Browser set up these profiles`.

### S5. Message ids

- Kebab-case, lower case, no camel case, no underscores. Scope them: `save-dialog-cancel-button`, not `cancel`
  (FR, "Message Identifiers").
- After `browser-`, use Gecko's family word for the feature: `neterror-`, `certerror-`, `tabcrashed-`, `identity-`,
  `urlbar-`, `tabbrowser-`, `tab-context-`, `main-context-menu-`, `downloads-`, `findbar-`, `places-`, `sanitize-`,
  `profile-window-`. It greps in both trees.
- End in the kind where it is one of Bingux's (`-title`, `-button`, `-tooltip`, `-notification`, `-label`,
  `-description`), as `docs/bingux-ui.md` says.
- Never build an id at run time. An explicit table keeps ids searchable (FR, "Avoid Generating Identifiers at
  Run-time"). Ours: `i18n_id!` tables, which is the same idea.
- Changing the meaning, or adding or removing an attribute, needs a new id in Gecko (FR, "Changes to Existing
  Messages"). Gecko adds a number: `main-context-menu-back-3`. LD prefers a better name to a number.
- Only `en-US` exists in `apps/browser/locale`, so until a translation lands every id may be renamed freely.

### S6. Attributes

| Gecko attribute    | Use                                | Ours                               |
| ------------------ | ---------------------------------- | ---------------------------------- |
| `.label`           | text of a menu item or a button    | the message value                  |
| `.tooltiptext`     | hover text                         | `.tooltip`                         |
| `.aria-label`      | the name a screen reader says      | `.a11y`                            |
| `.placeholder`     | empty field hint                   | `.placeholder`                     |
| `.accesskey`       | underlined mnemonic of a menu item | none: bingux-ui has no access keys |
| `.title`, `.value` | window and field text              | the message value                  |

Gecko puts a control's parts in one message (`downloads-cmd-retry` has a tooltip and a panel name). Do the same:
one message, attributes for the parts (FR, "Changes in Morphology"; `docs/bingux-ui.md`).

### S7. Comments for localisers

- Every message with a variable has a `#` comment above it naming each variable, its type and what it holds:

    ```text
    # This string is used on a new line below the add-on name
    # Variables:
    #   $name (String) - Add-on author name
    ```

    (FR, "Comments"; LD, "Add localization notes".) Ours writes `# $percent is the zoom.` in a sentence, same intent.

- A comment also goes on ambiguous English (`bookmark` as noun or verb), an accessibility string, or an adjective whose
  noun is not in the message (LD).
- `###` describes the file. `##` opens a group and applies to all that follow until an empty `##` (FR).

### S8. Whole sentences, no composing

- One message is one sentence a translator can reorder. No `format!`, no `{ $wants }` filled from other messages (LD,
  "Splitting and composing sentences", "Word order").
- Do not put a selector in the middle of a sentence (FR, "Variants and plurals"). Ours has two:
  `browser-keeping-*` (`{ $part -> [settings] … *[history] … }`) and `browser-permissions-prompt`.
- Gecko writes one question per kind: `Allow { $origin } to use your camera?` (WI), `Allow { $host } to access your
location?` (BP `geolocation.shareWithSite4`). It writes the combinations whole, too:
  `webrtc-allow-share-camera-and-microphone`.

### S9. Plurals and numbers

- A count is a number variable and the message selects `[one]` and `*[other]`. Pass a number, not a string (FR).
- `[1]` means the literal 1 only. Put `[0]` in its own message, because other languages' plural classes differ (FR).
- Code must not depend on a variant. Ours has `{ $count -> [1] [2] *[3] }` in `browser-downloads-line`, which makes
  the message a switch for logic (FR; F3).
- Numbers and dates go through `NUMBER()` and `DATETIME()` (LD, "Date, time and unit formatting"). A percent has no
  space: `{ NUMBER($percent) }%`.
- Size, speed and time: Gecko's shape is `4 minutes left — 1.1 of 11.1 GB (2.2 MB/sec)` (DU `download-utils-status`).

### S10. Spelling and voice

- American English: `Canceled` (DP `stateCanceled`), `color`, `organization`. The catalogue's header already says so.
  Ours has `Cancelled` and `colours`.
- Write to "you". Call the people who use it "people", not "users" (AC N-R).
- Say what happened, then what to do: `Check to make sure you’ve typed the website address correctly.` (NE
  `neterror-http-error-page`).
- Do not say "click" or "tap": say "select" or "choose" (AC A-D, S-T). Say "touch and hold", not "long press".

### S12. Connection words

Gecko says `Connection secure` and `Connection not secure`, with no "is" (BR `identity-connection-secure`,
`identity-connection-not-secure`). Mixed content is "Connection not secure" with the detail underneath, from BR
`identity-description-*`. Ours says "Connection is secure" and gives mixed content a title of its own.

### S13. Toasts

Gecko's toast is a "confirmation hint": short, past tense, no full stop: `Saved to bookmarks`, `Link copied`,
`Password saved` (CH; SH `confirmation-hint-link-copied`). Ours: `browser-history-cleared` is already that shape. An
error toast says what failed and what to do next.

### S14. Windows and tooltips

- The private window's title is `{ -brand-full-name } Private Browsing` (BR `browser-main-private-window-title`; macOS
  adds a dash). A page title and the product name join with an em dash (AC punctuation).
- A tab with no page is `New Tab` (TB `tabbrowser-empty-tab-title`).
- A shortcut in a tooltip is a variable: `Go back one page ({ $shortcut })` (BC `navbar-tooltip-back-3`). Ours writes
  "Back" and shows the keys in the menu only.

## Plan

### Rules for every commit

1. **One feature per commit.** Visible strings and ids move together, in the same commit as the code that asks for them.
2. **Two commits per feature**, in this order, so a regression names its kind:

    | Kind  | Subject                                            | Contains                                                                            | Proof                                                                          |
    | ----- | -------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
    | names | `refactor(browser): <feature> takes Gecko's names` | `git mv`, type, field, method, variant and module names. No string, no behaviour    | Snapshots byte-identical. Test count unchanged. Structure test green           |
    | words | `feat(browser): <feature> words follow Firefox's`  | ids, text, `.ftl` entries, comments for localisers, `tr!` and `i18n_id!` at the use | `ftl-check`, `copy-lint`, catalogue test. Changed images listed in the message |

3. **Fluent ids move with their `.ftl` entries.** A commit never leaves an id in code without its entry, or an entry
   without its use. The catalogue test (`i18n::check::crate_catalogue`) fails on both. No translation exists, so no
   migration and no `-2` suffix (S5).
4. **Each touched file ends commented** (Main, 2026-11-26, relaying Kieran):
    - a module comment saying what the feature does and how it fits;
    - a doc comment on every type, variant and non-trivial method: what it is for, its invariants, why it is shaped so;
    - a comment at each state transition and at each odd branch, wait or ordering;
    - plain ASCII, British English, short sentences.

    That applies to Rust comments. Strings keep Gecko's curly quotes and em dashes (S3).

5. **Docs follow.** The same commit updates paths and names in `docs/browser.md` and `docs/browser/*.md`, and, for a
   user-visible word, the screenshots that show it.
6. **Folder moves** use `git mv`, so history follows. `app/structure_tests.rs` (rules 1, 5 and 9 of `structure.md`) stays
   green: no `pub mod` in a feature, no free function outside the allowed files, the backend named only under `engine/`.

### Gates and proof

Run after every commit, on the box (`ga-box run <slug> ...`, wrapped in `flock /home/node/ga/heavy.lock`). There is no
cargo on this machine.

```sh
M=apps/browser/Cargo.toml
cargo build  --manifest-path $M
cargo test   --manifest-path $M --features snapshot
cargo clippy --manifest-path $M --all-targets --features snapshot -- -D warnings
cargo fmt    --manifest-path $M -- --check
python3 scripts/ftl-check.py && python3 scripts/copy-lint.py --no-captures && python3 scripts/ui-lint.py
```

Snapshots:

- Build with `--features snapshot`, run `--snapshot DIR` before and after, and `cmp` each `NAME-SIZE.png`.
- A names commit must show no difference.
- A words commit lists each image that changed and the message ids that changed it.
- If another agent commits to `apps/browser` or `crates/ui` meanwhile, take the baseline again from a detached
  worktree at the commit before yours (`structure.md`, "Snapshots").
