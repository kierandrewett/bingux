# Design rules

Kieran's standing design, behaviour and process rules for Bingux UI apps, taken from what he has told the agents, with the checks that would hold each one. Written 2026-10-29. It is a catalogue: it changes no code. `design/rules.json` has the same rules for tools.

Which check holds which rule, how to run them all (`make rules-check`) and how to add a rule or a check: `design/rules-checks.md`. The state of every rule after the last run: `design/rules-report.md`. The "Enforced by" text of this file is hand-written and was not checked against the checks; the registry (`python3 scripts/rules-check.py --registry`) is.

How to read it

- IDs (`SP-01`) are stable. A check, a test name or a commit message cites the ID.
- **Quote**: his words, verbatim, typos kept. `M0218` is the 219th user turn of the main session (2026-10-24 to 2026-10-29), `O0105` a turn of the earlier session where Settings was first built (2026-10-20 to 2026-10-24). The date is the quote's.
- **(P0 x6)** after an ID: priority and repeats. Repeats is the number of separate messages in which he raised it. P0 is raised three or more times, or twice in capitals; P1 twice; P2 once.
- **Enforced by** says what the repository has today. "none found" means no check in the scripts, the 17 layout rules, the a11y checks or the unit tests I read covers it. Nothing was run to confirm.
- **Proposed check** names the type: layout-lint rule over the captured tree, pixel test, token unit test, ui-lint source rule, a11y check, snapshot diff, scripted walk, or manual review with the reason.

Capture available to a check: `bingux_ui::snapshot` renders a window with no compositor and the inspector `Snapshot` gives per node `area`, `used.border`, `used.padding`, `used.content`, `margin`, `gap`, `corner_radii`, `font_size`, `opacity`, `fill`, `text`, `a11y.role`, `a11y.name`, `a11y.focusable` and `a11y.component` (packages/bingux-ui/src/inspector/snapshot.rs). PNGs and every 16 ms frame can be kept (`--keep`, `BINGUX_SETTINGS_SNAPSHOT_FRAMES`). Scripted input exists (`BINGUX_SETTINGS_SNAPSHOT_SCRIPT`: `down`, `move`, `up`, `touch_*`).

## The padding model

One scale on a 4 px grid (`S1` = 4, named as Tailwind names it), one table for sizes with a regular (mouse) and compact (finger, or window narrower than 740 px) value, one radius ladder. The rule behind most of it is Kieran's "padding/radii rule": a box inside a rounded box sits an inset in and its radius is the outer radius minus that inset, so the two curves are concentric (M0160, M0213, M0219). Values are in logical pixels, desktop first.

## Rules

### Spacing and padding (SP, 21 rules)

Numbers are in the padding model table above. "Equal" means within half a pixel.

| ID | Rule | Quote | Applies to | Enforced by | Proposed check |
|---|---|---|---|---|---|
| **SP-01** (P0 x6) | Padding is equal on both sides of an axis: content starts as far from the start edge as it ends from the end edge (left = right, top = bottom) unless the box is deliberately leading-aligned. | "padding on the right side of rows is wrong. and does not align with the left side" (M0010, 2026-10-24; also M0227, M0070, M0000, O0093, M0307) | Row, Group, popup body, tab strip, card, any box | layout-lint:uneven-padding (only boxes that declare equal padding and size to their content); unit: tokens field_insets_fit_the_field_and_the_row | layout-lint rule "inset-asymmetry": for every card, row, header, popup body and strip, measure the gap from the content run to each of the four edges of the border box (Node.area vs children union) and fail when left != right or top != bottom by more than 0.5 px; add the case the current rule skips (a box with no declared padding, such as the Files window edge). |
| **SP-02** (P0 x5) | A trailing button, switch, icon button or dropdown sits the same distance from the row's top, bottom and trailing edge (ROW_INSET 8 px for buttons, SWITCH_INSET for switches), so it is flush with the row's own padding. | "the right paddiong on this row should be equal to the y padding. so the button is flush with the edge/padding" (M0218, 2026-10-27; also M0264, M0204, M0307, M0194) | Row.trailing, HeaderBar, Banner/Toast, tab strip buttons, field trailing button | Tokens ROW_INSET, SWITCH_INSET, FIELD_INSET, NOTICE_PAD; unit: tokens field_insets_fit_the_field_and_the_row; notice_tests.rs. Alignment is measured on centres and edges of the captured tree; half a pixel is the tolerance.

|---|---|---|---|---|---|
